# Self-written Tbilisi padel booking sites — availability recon

Six one-off / self-written club sites, investigated 2026-07-30/31 against live HTTP
responses and the sites' own JS bundles. Every endpoint below was called; the samples
are literal excerpts of what came back. Anything I could not call is marked
**UNVERIFIED**.

The adapter contract this answers for: constructed with a club config + HTTP client,
`fetch(date_range)` returns only currently-**free** slots, each with a stable
`court_ref`, a human `court_label`, absolute `starts_at`/`ends_at`, and a deeplink.
See `lib/booking/adapters/gymbreeze.rb`.

## Comparison

| Site | Rendering | Endpoint | Auth | Granularity | Difficulty |
|---|---|---|---|---|---|
| [Lemans Padel](#lemans-padel--lemanspadelge) | WordPress page + vanilla-JS widget → XHR | `GET https://booking.lemanspadel.ge/api/availability?date=&duration=` (+ `/api/availability/courts`) | none | 30-min starts; free-court **count** per slot, court identity via 2nd call | **Easy — best of the six** |
| [Padel Gldani](#padel-gldani--padelgldanige) | Vite/React SPA → tRPC XHR | `GET https://padelgldani.ge/api/trpc/bookings.getBookedSlots?batch=1&input=…` | none | per court (ids 1–3), hourly | **Easy** (must invert booked→free) |
| [PadelHub](#padelhub--padelhubge) | Vite/React SPA → Supabase RPC | `POST https://gpypwkyuangjzgabagyi.supabase.co/rest/v1/rpc/get_booking_availability` | public Supabase anon key (embedded in bundle) | per court (UUIDs), hourly | **Easy–moderate** (invert + hard-coded grid) |
| [GAMO](#gamo--gamoge) | Laravel + Inertia SSR props; booking modal → XHR | `GET https://gamo.ge/en/book/availability?product_id=&date=` | none | per venue-product, 30-min interval | **Easy — but no Tbilisi padel venue** |
| [Padelio](#padelio--padelioge) | Vite/React SPA → own `/api` | `GET https://padelio.ge/api/timeslots/court/{id}?date=` | n/a | n/a | **Blocked — backend returns 503 `API_ORIGIN is not configured`** |
| [GPadel Tskneti](#gpadel-tskneti--gpadelge) | — | — | — | — | **Dead — `gpadel.ge` is NXDOMAIN** |

### Shared-platform finding: there is none

I looked hard for a common builder or a repeated endpoint shape. **All four live sites
run genuinely different stacks** — there is no adapter to collapse:

- `padelhub.ge` — Vite/React on **Vercel** (`server: Vercel`), backend is **Supabase**
  (`https://gpypwkyuangjzgabagyi.supabase.co`), CSP whitelists only `*.supabase.co`.
- `padelgldani.ge` — Vite/React behind **Express** on Cloudflare (`x-powered-by:
  Express`), backend is **tRPC v11 + superjson**. Media paths are `/manus-storage/…`
  and every JSX node carries `data-loc="client/src/pages/Booking.tsx:1461"` — i.e. this
  was generated by an AI app builder (Manus) from a `client/src` + tRPC template. Sole
  fingerprint I found; no other site in this set shares it.
- `booking.lemanspadel.ge` — hand-rolled **PHP on LiteSpeed** (`PHPSESSID`), separate
  subdomain from the WordPress marketing site.
- `gamo.ge` — **Laravel + Inertia + React** on nginx (`XSRF-TOKEN`/`gamo_session`
  cookies), a multi-sport marketplace, not a club site.

The one real consolidation available is a different one: **PadelHub and Padel Gldani
both expose *booked* slots and require the adapter to synthesise the free grid**, so
they can share a "grid minus bookings" helper even though the transports differ.

## PadelHub — padelhub.ge

**1. Rendering.** Client-rendered. `https://padelhub.ge/booking` (301 → `www.`) is a
7.8 KB Vite SPA shell with `<div id="root">` and an SEO-only `display:none` fallback;
the schedule is not in the HTML. Entry bundle
`https://www.padelhub.ge/assets/index-6X2JVo7Q.js`, booking chunk
`https://www.padelhub.ge/assets/BookingPage-6_I_7FFz.js`.

The bundle's CSP meta tag already gives the backend away:

```
connect-src 'self' https://*.supabase.co wss://*.supabase.co …
```

and `index-6X2JVo7Q.js` contains the project URL plus the anon JWT:

```
https://gpypwkyuangjzgabagyi.supabase.co
eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.eyJpc3MiOiJzdXBhYmFzZSIsInJlZiI6ImdweXB3a3l1YW5nanpnYWJhZ3lpIiwicm9sZSI6ImFub24iLCJpYXQiOjE3Nzg3MDczMTMsImV4cCI6MjA5NDI4MzMxM30.s_s7BS2fS_qir43c-m8URuT-3cZnlZ8xdBHG6a7Jazs
```

`BookingPage-6_I_7FFz.js` makes exactly two reads:

```js
mt.from("courts").select("*").eq("is_active",!0)
mt.rpc("get_booking_availability",{p_booking_date:u,p_court_id:w})
```

**2. Auth.** No login. The anon key is a Supabase *publishable* key — it is meant to
ship in the browser. Both calls succeed with just `apikey` + `Authorization: Bearer`
headers set to that key. Note the RLS boundary is real: `GET /rest/v1/bookings`
returns `{"code":"42501", … "permission denied for table bookings"}`, so the RPC is
the only door.

Courts —
`GET https://gpypwkyuangjzgabagyi.supabase.co/rest/v1/courts?select=*&is_active=eq.true`:

```json
[
  {"id":"0a0a2ddd-4f0d-4a66-a5c3-2d08bcf5eebd","name":"court_padel_open","sport_type":"padel","is_active":true},
  {"id":"7c36c5d8-8a2f-4021-ab76-6305ed6f85a1","name":"court_padel_closed","sport_type":"padel","is_active":true},
  {"id":"154545c2-e962-4d85-8e1a-9bf5bcfa4721","name":"court_pickleball","sport_type":"pickleball","is_active":true}
]
```

Availability —
`POST /rest/v1/rpc/get_booking_availability` with
`{"p_booking_date":"2026-07-31","p_court_id":"0a0a2ddd-…"}`:

```json
[{"time_slot":"21:00","booking_date":"2026-07-31","status":"confirmed","is_payment_hold":false},
 {"time_slot":"22:00","booking_date":"2026-07-31","status":"confirmed","is_payment_hold":false},
 {"time_slot":"20:00","booking_date":"2026-07-31","status":"confirmed","is_payment_hold":false},
 {"time_slot":"19:00","booking_date":"2026-07-31","status":"confirmed","is_payment_hold":false}]
```

`p_court_id: null` returns `[]` — the court id is mandatory, so it is 2 requests per
day (padel only) or 3 (with pickleball).

**3. Free-slots-only?** No — the opposite. It returns **taken** rows. Field is
`status`; the client keeps `status === "confirmed"`, plus `status === "cancelled"` rows
whose start is less than 2 hours away (a just-cancelled slot is not re-sold inside the
2-hour window). An adapter should treat `confirmed` ∪ (`cancelled` within 2 h) as
occupied and subtract from the grid, exactly as the site does.

**4. Granularity.** Per court, per hour. `court_ref` = the court UUID (stable, from
`/rest/v1/courts`). `court_label`: the `name` column is an i18n key
(`court_padel_open` / `court_padel_closed`), so the label has to be mapped in
`clubs.yml` — "Padel Open" / "Padel Closed" ("open" = outdoor, "closed" = indoor,
per the club's own `/courts/padel-open.jpg` imagery).

**5. Grid, hours, price, horizon.** All client-side, from `BookingPage-6_I_7FFz.js`:

```js
const Ve=["08:00","09:00",…,"22:00","23:00","00:00"], In=new Set(["00:00"]),
Mt=(e,t)=>{const s=new Date(`${e}T${t}:00+04:00`);return In.has(t)?sn(s,24):s}
const Je=3, ot={padel:60,pickleball:40}, St=40,
qr=new Set(["08:00",…,"14:00"]);  // padel is 40 GEL in this window, else 60
```

- Grid: hourly 08:00–23:00 **plus** 00:00, which belongs to the *next* calendar day
  (`+24 h`). Matches the advertised 08:00–01:00.
- Timezone is hard-coded `+04:00` / `Asia/Tbilisi`.
- Price: padel 40 GEL for 08:00–14:00 starts, 60 GEL otherwise; pickleball 40 GEL;
  racket rental 3 GEL.
- Horizon: the date picker is `disabled:{before:new Date}` with **no upper bound** —
  effectively unlimited. As with GymBreeze, far-future days will read 100 % free
  forever, so cap `max_days` in config.

**6. Deeplink.** `https://www.padelhub.ge/booking`. No date/time/court query
parameters — the only `URLSearchParams` read in the booking page is `?payment=failed`.

## Padel Gldani — padelgldani.ge

Brand parent `padelgroup.ge` is a separate Next.js marketing site whose only booking
link is `href="https://padelgldani.ge/booking/"` — no second booking system to chase.

**1. Rendering.** Client-rendered. `https://padelgldani.ge/en/booking` returns a
370 KB HTML that is still just a `<div id="root">` shell (the bulk is inline CSS/SEO);
one bundle, `https://padelgldani.ge/assets/index-9i6MKs2W.js`, which ends with:

```js
Ze.createClient({links:[WX({url:"/api/trpc",transformer:mA,
  fetch(e,t){return globalThis.fetch(e,{...t??{},credentials:"include"})}})]})
```

**tRPC v11 with an httpBatchLink at same-origin `/api/trpc`**, superjson transformer.
The routers seen in the bundle: `courts.list`, `courts.currentStatus`,
`bookings.getBookedSlots`, `bookings.checkAvailability`, `bookings.todayAvailability`,
`bookings.createHold`, `bookings.create`, plus an admin surface.

**2. Auth.** None for reads. Plain GET, no cookie, no CSRF header needed.

`GET https://padelgldani.ge/api/trpc/courts.list?batch=1&input={"0":{"json":null,"meta":{"values":["undefined"]}}}`:


```json

  {"startTime":"15:00","endTime":"20:00","bookingDate":"2026-07-31","isHold":false,"expiresAt":null,"sessionId":null},
  {"startTime":"23:00","endTime":"02:00","bookingDate":"2026-07-31","isHold":false,"expiresAt":null,"sessionId":null}]}}}]
```

**Batching works** — one HTTP request covers all three courts (and would cover 14 days
× 3 courts in a single call):

```
GET /api/trpc/bookings.getBookedSlots,bookings.getBookedSlots,bookings.getBookedSlots
    ?batch=1&input={"0":{"json":{"courtId":1,"date":"2026-08-01"}},

                    "2":{"json":{"courtId":3,"date":"2026-08-01"}}}

   {"result":{"data":{"json":[]}}},
   {"result":{"data":{"json":[]}}}]
```

Note the overnight spill in that last sample: asking for `2026-08-01` also returned the
`2026-07-31 23:00→02:00` booking, i.e. the query returns bookings **overlapping** the
requested day, not only those dated to it. Deduplicate on `(bookingDate, startTime)`.

There is also a today-only free-slot shortcut,
`GET /api/trpc/bookings.todayAvailability?batch=1&input={"0":{"json":null,"meta":{"values":["undefined"]}}}`:

```json
[{"result":{"data":{"json":{"freeToday":40,"courts":3,
 "courtFreeSlots":{"1":10,"2":16,"3":18},
 "courtFreeHours":{"1":["08:00","09:00","10:00","11:00","12:00","13:00","14:00","20:00","21:00","22:00"],
                   "2":["08:00",…,"19:00","22:00","23:00"],
                   "3":["08:00",…,"22:00","23:00"]}}}}}]
```

Free hours per court, already inverted — but only for the current day, so it cannot
carry a multi-day `date_range`. Useful as a cheap cross-check of the inversion logic.
(The `courtFreeSlots` counts do not match the `courtFreeHours` array lengths for court
2 — 16 vs 14 — probably because the counts include the post-midnight hours. Cause
**UNVERIFIED**; prefer `getBookedSlots`.)

**3. Free-slots-only?** No — booked intervals, as `startTime`/`endTime` ranges (not
per-hour rows). `isHold: true` marks a payment hold with `expiresAt`; treat holds as
occupied. An hour is booked when `start ∈ [startTime, endTime)` after mapping
`hour < 8` to `hour + 24` (the site's own `Wr()` helper does exactly this).

**4. Granularity.** Per court, per hour. `court_ref` = `1` / `2` / `3` (stable
integers). `court_label` = the `name` field, already human ("Croco Court I -
გადახურული" = covered; "Court III - ღია" = open-air).

**5. Grid, hours, price, horizon.** From the bundle:

```js
function wAe(){const e=[];for(let t=8;t<24;t++)e.push(`${String(t).padStart(2,"0")}:00`);
  return e.push("00:00","01:00","02:00"),e}

function SAe(){…for(let n=0;n<14;n++){…}…}   // date chips
```

- Bookable starts: hourly 08:00 → 01:00 (02:00 is the closing time, never selectable).
  Matches the site's own meta description, "ღიაა 08:00–02:00".
- Price: court 1 & 2 — 60 GEL weekday / 70 weekend; court 3 — 50 / 60.
- Horizon: **14 days** including today.

**6. Deeplink.** `https://padelgldani.ge/booking` (also `/en/booking`). It accepts
`?court=<id>`: the booking page reads
`new URLSearchParams(window.location.search).get("court")` and jumps straight to the
date step with that court preselected. No date/time prefill.

## Lemans Padel — lemanspadel.ge

**The cleanest source of the six.** It is the only one that hands back an explicit
free/busy flag *and* a free-court count.

**1. Rendering.** Hybrid. `https://lemanspadel.ge/` is WordPress 7.0.2 + WooCommerce +
Elementor, but the booking page `https://lemanspadel.ge/book-padel/` is a custom form
driven by a vanilla-JS widget served from a separate host:

```html
<div id="booking-app" data-api-base="https://booking.lemanspadel.ge"
     data-prefill-code="" data-attribution-prefill="[]"
     data-business-today="2026-07-30" data-day-close-hour="4">
<script src="https://booking.lemanspadel.ge/assets/js/public/booking-app.js?v=1783440643">
```

The widget calls `/api/courts`, `/api/availability`, `/api/availability/courts`,
`/api/availability/calendar`, `/api/inventory`, `/api/pricing`, `/api/discount/validate`,
`/api/booking` — all on `booking.lemanspadel.ge`. Nothing is server-rendered.

**2. Auth.** None. The API sets a `PHPSESSID` cookie but does not require one for
reads; every call below was made cold with no cookie jar.

`GET https://booking.lemanspadel.ge/api/courts`:

`GET /api/availability/courts?date=2026-07-31&start_time=19:00&duration=60` names the
courts that are actually free at that start:

```json
{"date":"2026-07-31","start_time":"19:00","duration":60,"courts":[
 {"id":1,"court_number":1,"name":"კორტი #1","slug":"court-1","display_order":1,"price":70}]}
```

…and returns `"courts":[]` for the sold-out 20:00.

`GET /api/availability/calendar?year=2026&month=8&duration=60` → per-day
`{"date":"2026-08-01","status":"available"}`, useful to skip whole closed days cheaply.

**3. Free-slots-only?** All slots, with **`available` (boolean)** and
**`available_courts` (integer)**. This is the one source where "only free" is a
one-line filter and no grid has to be synthesised.

**4. Granularity.** Two levels:
- `/api/availability` — per **hour-start**, every 30 minutes, aggregated across the
  club (`available_courts` = how many of the 4 are free). Enough for an hour-level
  adapter, one request per day.
- `/api/availability/courts` — per **court**, for one `(date, start_time, duration)`.
  `court_ref` = `id` (1–4, stable) or `slug` (`court-1`…). `court_label` = `name`
  (`კორტი #1`). Court-level costs one extra request per candidate start, so only pay
  for it on starts where `0 < available_courts < 4`.

**5. Grid, hours, price, horizon.**
- Starts every 30 min from 08:00 through 01:00 (last slot `01:00–02:00`, dated to the
  next day in `start_datetime`). `data-day-close-hour="4"` — the business day rolls at
  04:00, and `data-business-today` was `2026-07-30` when queried at 22:1x UTC on the
  30th, i.e. `start_datetime` is **local Tbilisi wall-clock, `Asia/Tbilisi`, no offset
  in the string**.
- Durations 60 / 90 / 120 min; price 70 / 105 / 140 GEL, identical on all four courts.
- Horizon: **none server-side** — `?date=2027-03-01` and even a past `2026-07-01`
  answer with a full free grid. The widget's flatpickr sets `minDate` = business today
  and **no `maxDate`**. So cap `max_days` in config or every far date reads free.

**6. Deeplink.** `https://lemanspadel.ge/book-padel/`. The widget supports a prefill
(`date`, `time`, `court_id`, `duration_min`) but it arrives via the server-rendered
`data-attribution-prefill` attribute, not query parameters —
`?date=…&time=…&court_id=…` left it as `[]`, and the widget JS never reads
`location.search`. **UNVERIFIED**: what triggers it (probably a partner attribution
code, cf. `data-prefill-code` / `data-attribution-source-id`). Assume a plain page link.

## Padelio — padelio.ge

**Live front end, dead back end.** Worth watching, not worth an adapter today.

**1. Rendering.** Client-rendered Vite SPA; `https://padelio.ge/` is a 5 KB shell with
`<div id="root"></div>` and bundle `https://padelio.ge/assets/index-cc801870.js`. The
axios setup:

```js
const ch=({}.VITE_API_URL)?.trim(),
 hb=typeof window<"u"&&/(^|\.)padelio\.ge$/.test(window.location.hostname),
 $m=hb||!ch?"/api":`${ch.replace(/\/$/,"")}/api`,
 se=zm.create({baseURL:$m,withCredentials:!0});
```

Availability call:

```js
const{data:n}=await se.get(`/timeslots/court/${e}?date=${t}`);
```

Other routes in the bundle: `/courts`, `/courts/{id}`, `/bookings`, `/bookings/my`,
`/bookings/{id}/cancel`, `/auth/login|register|logout|callback`, `/payments/initiate`,
`/matches/*`.

**2. Auth / liveness.** The `/api` path is a Cloudflare-fronted proxy that is not
wired up:

```
$ curl https://padelio.ge/api/courts
HTTP/2 503 ; server: cloudflare
{"message":"API_ORIGIN is not configured."}

$ curl "https://padelio.ge/api/timeslots/court/demo-court-one-001?date=2026-08-01"
HTTP/2 503
{"message":"API_ORIGIN is not configured."}
```

Every `/api/*` path returns the same 503. With `/courts` empty the site renders "No
courts available yet."

The bundle even carries a hard-coded demo fallback that fires when the API returns
nothing — `{id:"demo-venue-tbilisi-001",name:"Padelio Demo Venue",address:"10
Saburtalo Street, Tbilisi"}` with "Court one"/"Court two" and a synthetic all-free
30-minute grid. **Anything a browser shows on padelio.ge today is fabricated
client-side, not real availability.** Do not scrape the rendered page.

**3–5.** From the bundle, so **UNVERIFIED against a live response**: slot status is an
enum `AVAILABLE | LOCKED | BOOKED` (`Hm` in the bundle) plus a booking-mode enum
`FULL | SPLIT`; the demo generator emits **30-minute** slots with ISO `startTime` /
`endTime`; marketing copy says "Book 1, 1.5, or 2 hours. 30-minute slots", and the
JSON-LD on the shell declares `"opens":"08:00","closes":"22:00"` daily. There is a
real API shape here (`/timeslots/court/{courtId}?date=`, returning objects with
`id`, `courtId`, `startTime`, `endTime`) — it just has no origin behind it.

**6. Deeplink.** `https://padelio.ge/courts/{courtId}` — **UNVERIFIED**, no court ids
exist to test with.

**Recommendation:** no adapter. Re-probe `https://padelio.ge/api/courts` occasionally;
the day it stops answering 503 the site is ready and the endpoints above are already
known.

## GPadel Tskneti — gpadel.ge

**Dead. The domain does not exist.**

```
$ dig gpadel.ge
;; ->>HEADER<<- opcode: QUERY, status: NXDOMAIN
;; flags: qr rd ra ad; QUERY: 1, ANSWER: 0, AUTHORITY: 0, ADDITIONAL: 0
$ dig +short NS gpadel.ge      # empty
$ dig +short SOA gpadel.ge     # empty
$ curl https://gpadel.ge/
curl: (6) Could not resolve host: gpadel.ge
```

No A record, no NS, no SOA — the `.ge` registry returns NXDOMAIN, so this is not a
parked or misconfigured site, the delegation is gone. `www.gpadel.ge`,
`booking.gpadel.ge`, `g-padel.ge`, `gpadeltskneti.ge` and `gpadel.club` are equally
absent. `gpadel.com` does resolve but is a GoDaddy parking page (`img1.wsimg.com`
assets, `<title>gpadel.com</title>`), unrelated to the club.

The club is real and directories still point at the dead domain — MyPadelWay's Tbilisi
listing gives "GPadel In Tskneti → https://gpadel.ge/"
(<https://mypadelway.com/ge/city/tbilisi>), and adidaspadel.ge lists "GPadel Tskneti"
as one of its installed projects. So: 8 courts plausibly exist, **online booking does
not**. **UNVERIFIED** whether they moved to Instagram/phone booking or to another
platform under a name I did not find.

**Recommendation:** no adapter. If the club matters, ask them directly what URL
replaced `gpadel.ge`.

**Not a club site — a multi-sport marketplace. And its padel inventory is one venue in
Rustavi, not Free University.**

`https://gamo.ge/en/padel` and `/en/padel/` both **404**; the real site is
`https://gamo.ge/en` (Laravel + Inertia).

**1. Rendering.** Server-rendered Inertia props in the HTML — the landing page ships
`categories`, `recommended`, `freeToday`, `venues` etc. inside
`<div id="app" data-page="{…json…}">`, no XHR needed to read the catalogue. The
booking modal then fetches availability by XHR.

**2. Auth.** None for catalogue or availability (booking itself needs an account +
verified phone). Session cookies are set but not required.

**3. The padel gap.** From the landing props:

```json
{"id":47,"slug":"-10","name":"Padel","sportKey":"padel","venuesCount":1}
```

**One** padel venue on the whole platform: `id 196`, `padelhiggs`, **PadelHiggs,
Rustavi, Giorgi Nikoladze Str.**, 60 GEL/h. The Tbilisi venue list
(`https://gamo.ge/en/products`, `total: 37`) contains **zero** `sportKey: "padel"`
rows. The Free University connection in the brief is football and basketball, not
padel: `160 newton-free-school-stadium` (Football) and
`162 newton-free-school-basketball-court` (Basketball), both Saburtalo,
lat/lng 41.72003/44.70762. **There is no GAMO padel court at Free University in the
catalogue as of 2026-07-31.**

**4. Endpoint (for completeness / if a Tbilisi padel venue appears later).**

Availability, from `https://gamo.ge/build/assets/app-CoRPEBvZ.js`:

```js
fetch(`/${hQ()}/book/availability?product_id=${e}&date=${t}`,
      {headers:{Accept:"application/json"},credentials:"same-origin"})
  .then(s=>s.json()).then(s=>{const i=s.taken??[]; …})
```

`GET https://gamo.ge/en/book/availability?product_id=196&date=2026-08-01`:

```json
{"date":"2026-08-01","product_id":196,"taken":[]}
```

Returns **taken** slots, not free ones. `taken` came back empty for every product and
date I tried (196 padel, 154 football, today and tomorrow) — the platform looks very
new, so I could not observe a populated entry. Element shape is `{date, time}` per the
client's `q0(product, t.date, t.time, taken)` check — **UNVERIFIED** against a real
non-empty response.

Per-venue booking metadata, `GET https://gamo.ge/en/book/data?product=196`:

```json
{"id":196,"slug":"padelhiggs","name":"PadelHiggs","category_id":47,"sport":"Padel",
 "city":"Rustavi","basePrice":60,"singleSlot":false,
 "minBookMinutes":60,"slotInterval":30,"minAdvanceHours":3,
 "activeHours":{"monday":[{"start":"08:00","end":"00:00"}], …every day the same…},
 "dynamicPrices":{"monday":[], …},"blockedRanges":[],"addons":[]}
```

So the grid is synthesised client-side from `activeHours` + `slotInterval` (30 min),
minimum booking `minBookMinutes` (60), and nothing within `minAdvanceHours` (3 h) is
bookable. The widget scans up to **60 days** ahead for the first free slot
(`I.getTime()+60*24*60*6e4`), which is a fair read of the horizon.

**5. Granularity.** Per *product*, and a product **is** a single court/field — GAMO
models "Zaza Pachulia Court A/B/C" as three products. So `court_ref` = product id,
`court_label` = product name, and a multi-court club would be several products to poll.

**6. Deeplink.** `https://gamo.ge/en/product/{slug}` (e.g.
`https://gamo.ge/en/product/padelhiggs`); booking opens in a modal on that page. There
is also a native app (`ge.gamo.app` / App Store id 6762342470).

**Recommendation:** no adapter for a Tbilisi padel watcher today. Worth a periodic
re-check of `/en/book/data` (`categories[] where sportKey=="padel" → venuesCount`);
the API is trivial to adapt the moment a Tbilisi padel venue is listed.

## Suggested next steps

   `available_courts` count means "last court just freed up" is directly observable
   without any inversion.

   possibility of a key rotation.
